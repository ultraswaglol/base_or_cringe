# Base or Cringe (База или Кринж)

Интерактивное мобильное приложение-квиз, разработанное на Flutter с использованием принципов чистой архитектуры (Clean Architecture) и паттерна BLoC. Проект ориентирован на платформу Android и оптимизирован для публикации в RuStore.

## Технический стек

- **Фреймворк:** Flutter
- **Архитектура:** Clean Architecture (Feature-First) с разделением слоев (Data, Domain, Presentation)
- **Управление состоянием:** flutter_bloc (BLoC для игрового процесса, Cubit для экрана результатов)
- **Внедрение зависимостей:** GetIt (Service Locator)
- **Анимации и жесты:** Интерактивный виджет на основе GestureDetector и AnimationController (механика свайпа карт влево/вправо)
- **Монетизация:** Yandex Mobile Ads SDK v8.0.0 (межстраничная полноэкранная реклама и адаптивные баннеры)
- **Хранение данных:** Локальная база вопросов в формате JSON, загружаемая асинхронно через AssetBundle

## Структура проекта

Код проекта разделен на независимые модули (фичи) для обеспечения масштабируемости и простоты тестирования:

```text

lib/
├── core/                           # Общие модули приложения
│   ├── di/                         # Конфигурация внедрения зависимостей (GetIt)
│   ├── theme/                      # Глобальная визуальная тема (Неоновый брутализм)
│   └── widgets/                    # Общие виджеты (например, YandexBannerWidget)
└── features/                       # Изолированные фичи
    ├── game/                       # Фича игрового процесса
    │   ├── data/                   # Слой данных (модели, локальные источники данных, репозитории)
    │   ├── domain/                 # Бизнес-логика (сущности, контракты репозиториев)
    │   └── presentation/           # Слой отображения (BLoC, страницы, виджеты карт)
    └── assessment/                 # Фича подсчета результатов и диагностики
        ├── domain/                 # Бизнес-логика (вычисление психотипа)
        └── presentation/           # Слой отображения (Cubit, экран результатов)

 ```

Особенности технической реализации

Механика свайпа карт (Tinder-style)
Управление карточками реализовано через GestureDetector без использования тяжелых сторонних библиотек. Виджет SwipeableCard отслеживает координаты жеста, рассчитывает угол наклона и выводит динамические наложения-штампы ("БАЗА" или "КРИНЖ") в зависимости от направления сдвига. Реализован пружинистый возврат в центр (Curves.easeOutBack) при незавершенном жесте и улет карты за экран при преодолении порога в 120 пикселей.

Тактильная отдача (Haptic Feedback)
Внедрена двухзонная тактильная отдача через HapticFeedback:

Легкий щелчок (selectionClick) при пересечении порога свайпа для информирования пользователя о достижении критической точки.

Средний импульс (mediumImpact) при подтверждении выбора (улете карты) или при нажатии на физические кнопки интерфейса.

Алгоритм расчета результатов
Расчет итогового психологического профиля абстрагирован от конкретных идентификаторов вопросов (соблюдение принципа Open/Closed из SOLID). Каждая карточка в JSON-базе самостоятельно содержит метаданные о том, какую черту характера прокачивает выбор пользователя (Sigma, Toxic или Pleaser). Окончательный вердикт вычисляется по строгому математическому превосходству доминирующего признака.

Монетизация Yandex Ads SDK v8.0.0
Баннерная реклама: Адаптивный баннер YandexBannerWidget вычисляется динамически на основе ширины экрана устройства (BannerAdSize.sticky). Интегрирована изоляция слоя рендеринга нативного AndroidView с помощью RepaintBoundary, что предотвращает пропуски обновления поверхностей (skipped surface) и гарантирует отрисовку текстур.

Межстраничная реклама: Реализована фоновая предзагрузка через InterstitialAdLoader во время отображения результатов. Показ осуществляется с вероятностью 50% при переходе на повторный цикл игры для минимизации раздражения пользователей и удержания высокого eCPM.

Инструкция по сборке и запуску

Предварительные требования
Установленный Flutter SDK

Настроенный Android SDK

Шаги для запуска:
Клонирование репозитория и получение зависимостей:

```code
git clone <url-репозитория>
cd base_or_cringe
flutter pub get
```

Генерация системных иконок приложения:
При изменении иконки в ассетах выполните команду для генерации ресурсов под все плотности экранов Android:

```code
flutter pub run flutter_launcher_icons
```
Запуск проекта на устройстве или эмуляторе:
Для тестирования нативных элементов разметки (включая рекламу) на некоторых версиях Android с эмуляторами рекомендуется отключать Impeller:

```code
flutter run --no-impeller
```

Сборка релизного билда (AAB) для загрузки в RuStore:

```code
flutter build appbundle --release
```

Настройка рекламных блоков
Рабочие идентификаторы блоков (AdUnitId) настраиваются в файле:
lib/features/assessment/presentation/pages/assessment_page.dart

Для локального тестирования по умолчанию прописаны тестовые ID Яндекса (demo-banner-yandex и demo-interstitial-yandex). Перед релизом замените их на продуктовые ключи формата R-M-XXXXXX-Y.
